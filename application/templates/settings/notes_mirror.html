Notes on a share

Your notes as Markdown files in a WebDAV folder — a Synology share, say — with each note's images and attachments in an _assets folder beside it. Point DEVONthink (or Obsidian, or Finder) at that folder and it reads them; edit them there and the changes come back. Folders match your notes tree, and moving or renaming a file over there moves or renames the note here.

A Tasks folder beside the notes: one Markdown file per task, its comments underneath, filed the way your projects are. This half is a copy — edits over there are overwritten, not read back. Recurring tasks are not written (a weekly review would only pile up one file per repetition). A task you finish moves into Tasks/Archive, into the same place in the same tree, and comes back out when you reopen it; a task you delete goes there too and is never touched again. Nothing under Tasks is deleted, so the history stays on the share.

Worth knowing

  • A file deleted over there moves its note to the Cairn trash — never a hard delete. If the share answers but is empty, the round deletes nothing at all and says so.
  • If a note and its file both changed since the last round, the note keeps your Cairn text and the file's version is written beside it as … (conflict …).md, which comes back as its own note. Nothing is merged and nothing is dropped.
  • Each file carries a cairn-id in its front matter. That is how a note survives being renamed or moved over there — keep the line and you can reorganise the folder freely.
  • The share must be reachable from the server Cairn runs on. A private address (LAN or VPN) is refused unless the deployment sets BKTODO_MIRROR_ALLOW_PRIVATE=1.
